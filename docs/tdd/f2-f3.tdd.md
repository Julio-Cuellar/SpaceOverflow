## 1. User journeys

1. As the **system**, I want to evaluate each batch of readings against a rule catalog with a source and evidence state, so I can raise auditable alerts.
2. As the **crew**, I want an alert not to flicker, not to be duplicated and to resolve itself when everything returns to normal.
3. As the **crew**, I want to acknowledge an alert only once, with no repeated events.
4. As the **system**, I want to receive readings in batches idempotently and announce them with a single event per batch.
5. As a **demo**, I want a zone simulator with scenarios (slow CO₂, leak, humidity, O₂ failure, heat) that follows the standard's sampling frequencies.
6. As a **UI developer**, I want to query the rule catalog with its version, and have each zone's readings available to other modules through a facade.

## 3. Incidents during the cycle (as they happened)

1. **One of my expectations was wrong** in the handler: with the test's scaled window, a PIO₂ of 121 mmHg already meets the absolute limit (122), so `env-pio2-abs-low` is raised and not `env-pio2-low`. The test was fixed, not the engine.
2. **F3's design exposed two defects in F2's rules**, which were fixed with tests first:
   - The trend detector required 20 baseline points, but the atmosphere is sampled every 5 s (standard V2 6001). It would never have fired. The parameters became per-rule.
   - The pressure rate-of-change rule used a 60 s window, in which a real leak averages about 6 psi/min and does not reach 13.5. It became 10 s.
3. **A leak test failed because of my test case:** at second 30 of an exponential leak the change in 10 s is 0.97 psi and is exempt under the "more than 1.0 psi" rule. It was fixed to evaluate the first 10 s and a test was added that documents the exemption.
4. **19 integration tests failed at once** because `tests/conftest.py` did not include the Telemetry tables in the cleanup: a text replacement I made was not applied because `ruff format` had already reformatted the list. It became visible because one test's data appeared in the next one.
5. **A text replacement in the engine was not applied either** for the same reason. It was detected with `grep` and edited against the real text.
6. **Four quality warnings at the end:** a leftover `type: ignore`, a generic converted to Python 3.12 syntax, a long SQL line and the import order. Fixed without relaxing strict mypy.
